# 서비스 범위

같이온은 부모님과 여행을 준비하는 성인 자녀가 큰틀을 정하고, 부모님이 구체적인 후보에서 원하는 경험을 선택하는 가족 여행 설계 도우미이다.

## 한 장면으로 이해하기

자녀가 테마 장소에서 가족사진, 전통시장, 점심, 카페를 후보로 준비한다. 어머니는 테마 장소 사진을 필수로 고르고, 아버지도 함께 먹을 점심과 휴식을 확인한다. A안은 시장 관람까지 남기고 B안은 테마 장소의 짧은 접근과 휴식을 중심으로 구성한다. 어느 안에서든 필수 사진 경험이 유지되는지 보여준다.

이동 중 쉬고 싶다는 요청이 오면 완료한 관람과 식사를 바꾸지 않고 남은 구간만 짧은 이용 방식으로 다시 검사한다. 가능한 안이 없으면 조건 변경과 추가 확인이 필요함을 표시한다. 다른 장소의 사진을 원래 경험과 같은 것으로 처리하지 않는다.

## 초기 범위

서비스의 첫 목표 범위는 한 권역의 차량 동반 당일여행, 부모님 2명과 자녀 1명, 후보 장소 12곳, 일정 반영 최대 6곳, 관람·접근 방식 최대 12개이다. 경주를 우선 조사하되 관광공사·시설 안내에서 필요한 정보를 확보한 뒤 시범 권역을 정한다. 서로 다른 지역을 한 동선으로 묶지 않는다.

현재 실행 데모에는 가상 후보 6곳과 이용 방식 12개가 있다. 부모님에게 보여줄 후보는 최대 4곳으로 제한하며, 이는 초기 화면 체험 범위이다. 목표 후보 12곳의 수집·선별 흐름과 실제 권역 데이터는 아직 구현하지 않았다. 취향 선택부터 소개·수정·추억 카드까지 한 흐름을 구현했으며 실제 관광 정보·공연 일정·예약·결제는 연결하지 않았다.

조건 검사 엔진은 특정 권역명에 의존하지 않는다. 실제 데이터 연결 시 관광 기본 정보는 여러 권역에서 불러올 수 있도록 설계하되, 보행·계단·접근 정보 확인은 시범 권역에 집중한다.

## 세 가지 핵심 기능

1. **사진 선택과 선택형 테마** — 자녀가 후보를 추리고 부모님이 O/X·건너뛰기와 우선 경험을 고른다. 직접 선택과 자녀의 대화 확인을 구분한다. 목표 흐름에서는 부모님별 우선 경험 1~2개를 확인하고 모두 좋아요인 경우에도 우선순위를 묻는다. AI 입력 구조화·확인 질문과 실제 테마 출처 수집은 후속 구현이다.
2. **선택한 경험을 지키는 일정 설계** — 장소의 접근·관람·휴식·출구 연결을 나누고 전체·짧은 관람의 대안 최대 2개를 비교한다. 필수 경험·예약·총보행·연속 보행·계단·운영·이동·식사를 검사한다. 완료 구간은 유지하고 남은 일정만 재검사하며 두 분의 확인 후 같은 일정 버전으로 반영한다.
3. **여행 소개와 가족 카드** — 확정 일정과 선택 이유를 모바일 소개 및 인쇄용 한 장 자료로 보여준다. 현재는 브라우저에서 기본 캐릭터와 선택한 사진을 합성한다. 이미지 변환과 Python 기반 카드 합성은 후속 구현이다.

## 조건 입력 원칙

목표 입력은 걷기 편한 시간·휴식 간격·계단 이용 여부·확인한 보행 상한과 식사의 매운 정도·음식 질감·회피 음식·입식 좌석·식사 시간이다. 나이나 질환명으로 조건을 추정하지 않고 시간을 임의의 거리로 환산하지 않는다. 미확인 값은 확인된 값과 구분한다.

현재 코드는 가족 단위의 총보행·연속 보행 상한, 계단 회피, 맵지 않은 메뉴, 예산, 식사 예약 시간과 입식 좌석을 검사한다. 부모님별 상세 체력·식성 입력, 음식 질감·회피 음식·휴식 간격 검사는 후속 범위이며 구현 완료로 표시하지 않는다.

## 화면 설계

자녀 화면은 설정·응답 취합·대안 비교·변경 내용을 제공한다. 부모님 화면은 사진 영역, 짧은 경험 설명, 큰 O/X 버튼, 건너뛰기, 필수 경험 표시를 중심으로 한다. 두 화면에서 같은 일정 버전을 보여준다. 초록색 기본 버튼, 사진을 중심으로 한 O/X 카드, 나란한 A·B안, 남은 구간 변경 요약, 여행 소개와 가족 카드의 확정 디자인을 반영했다.

카드는 실제 장소 사진을 넣을 수 있다. 기본 화면에는 확정 디자인의 예시 사진과 가상 일러스트를 사용하며 실제 시설 정보는 확인 전 상태이다. 자녀는 6개 가상 후보 중 최대 4개를 부모님께 보여준다. 여행 판단용 장소 자료와 가족 캐릭터 카드를 구분한다.

## 팬심·작품 테마

좋아하는 가수·배우·작품은 선택형 동기이다. 인물·작품과 장소의 관계를 공식 공개 안내로 확인한 뒤 “관련 장소에서 사진 남기기” 등 행동과 연결한다. 첫 테마는 한 가지로 제한하며 시범 권역 안의 관련 장소·촬영 풍경·예매한 지역 공연과 식사를 연결한다. 인물·소속사와의 공식 협업으로 표현하지 않는다. 확인한 관계의 출처·확인일을 저장하는 실제 데이터 수집은 후속 구현이다.

## 가족 캐릭터 카드

지브리 스타일 등 사진 변환에 대한 관심을 여행 초대와 추억 카드로 연결하는 기능을 구상했다. 현재는 자체 작성한 기본 가족 캐릭터 템플릿과 사용자가 선택한 사진을 합성한다. 사진을 그림으로 바꾸는 AI 기능은 구현하지 않았다.

후속 단계에서는 Hugging Face의 이미지 변환 모델을 검토하고 사진 속 가족 모두가 동의한 사진으로 한 가지 스타일을 생성한다. Python 기반 합성으로 카드에 적용하고 AI 생성 이미지임을 표시한다. 모델의 라이선스·사진 처리 방식·보관 정책을 확인한 뒤 연동하며 아직 모델을 선정하거나 실행하지 않았다. 실제 장소의 모습이나 접근 조건은 생성 이미지로 판단하지 않는다. 얼굴 사진 없이도 기본 캐릭터로 이용하도록 한다.

## 상담 자료와 데이터 보완

부모님이 확인한 필수 경험·이동·식사 조건을 한 장 자료로 정리해 여행 상품 탐색과 상담에 활용하는 것을 목표로 한다. 현재 인쇄 기능은 가상 일정의 안내용이며 여행사 연계는 미구현이다. 동의받은 이용 후기를 데이터 보완 후보로 모으는 기능도 후속 범위이며, 개인의 후기를 일반적인 접근성 사실로 확정하지 않는다.

## 다음 구현 순서

1. 실제 한 권역의 장소·이용 방식 자료에 출처·확인일·불확실성 상태를 기록한다.
2. LLM 입력 해석과 후보 설명을 연결한다. 코드 검사의 결과를 바꾸는 권한은 주지 않는다.
3. 가족 초대 링크와 역할별 인증·권한을 연결한다.
4. 동의한 사진의 캐릭터 변환 API와 실제 가족 사용성 검증을 진행한다.

사용자 인터뷰, 조율 시간 개선 수치, 추천 정확도, 운영 성과는 아직 측정하지 않았다.
