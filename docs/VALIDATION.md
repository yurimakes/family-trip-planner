# 검증 기록

이 문서는 구현한 코드의 검사 범위를 기록한다. 사용자 조사나 실제 여행 성능을 의미하지 않는다.

기존 검증 결과(2026-10-12): **Windows·Python 3.13 환경에서 Python 테스트 39개와 JavaScript 테스트 4개 모두 통과**했다. 선택형 FastAPI 어댑터 테스트도 포함하며 건너뛴 테스트는 없다. 당시 공개 파일 44개 검사에서 발견 사항은 0건이었다.

공개 데모 구현 후 최신 [GitHub Actions 실행](https://github.com/yurimakes/family-trip-planner/actions/runs/38332533566)(2026-10-13): **Windows·Linux 각각 Python 43개와 JavaScript 5개 모두 통과**했다. 선택형 FastAPI 검사도 통과했고 건너뛴 테스트는 없다. 공개 파일 49개 검사에서 발견 사항 0건, JavaScript 구문 검사와 19개 공개 파일 빌드도 두 환경에서 통과했다. 해당 실행의 게시 작업은 PR이므로 건너뛰었다.

선택형 FastAPI 의존성이 없는 로컬 Linux 실행에서는 Python 43개 중 42개 통과·1개 건너뜀이었고 JavaScript 5개가 통과했다. Actions는 선택 의존성을 설치한 환경의 별도 결과이다.

SQLite 연결은 트랜잭션 성공·실패와 관계없이 닫도록 수정했다. 연결 종료 및 실패한 변경의 롤백을 검사하는 회귀 테스트 2개를 추가했고, Windows 재실행에서도 통과했다. JavaScript 테스트에서 실행하는 Python 하위 프로세스는 `-X utf8`로 표준 입출력 인코딩을 고정한다. 한글 일정 데이터의 비교와 실제 Python 서비스 연결 검사도 통과했다.

## 검증의 한계

확정 디자인을 반영한 뒤 프런트엔드 상태 검사와 실제 Python 서비스 연결 검사를 실행했다. 프런트엔드 상태 검사는 DOM 대체 객체를 사용하며 실제 브라우저 렌더링 검사는 아니다. 아래 Windows 브라우저 확인과 구분한다. 실제 모바일 화면·Web Share 실행·물리 프린터 출력은 검증하지 않았다. 공개 URL의 실제 접속과 새 화면 전환의 브라우저 확인도 대기 상태이다.

FastAPI 어댑터의 기본 API는 Windows에서 `TestClient`로 검증했다. 별도 Uvicorn 서버 기동, 외부 배포, 운영 환경의 동시 요청과 성능은 이 테스트 범위에 포함하지 않는다.

거리·시간·비용은 가상 값이다. 실제 시설 접근성, 지도 거리, 운영시간, AI 응답 품질, 실제 가족의 선택·조율 시간은 검증하지 않았다.

## 수동 브라우저 확인

2026-10-12~13 Windows 로컬 웹의 첨부 화면·다운로드 결과와 사용자 확인으로 아래 상태를 확인했다. 모바일 기기와 모든 상호작용을 검증한 결과는 아니다. 사용자가 선택한 이미지는 공개 저장소에 포함하지 않는다.

| 항목 | 확인 상태 |
| --- | --- |
| 초기 화면 | 자녀·부모님 화면과 사진 카드 표시 확인 |
| 일정 확정 후 안내 | 두 화면에 같은 일정 내용과 `일정 v1` 표시 확인 |
| 자녀 소개 화면 헤더 | 좁은 그리드 적용을 수정한 뒤 두 화면의 같이온 로고 한 줄 표시 재확인 |
| 남은 일정 수정안 | 완료 1개·남은 보행 300m·연속 보행 100m 입력과 남은 거리 120–180m 표시 확인. 최종 v2 반영은 자동 검사 범위이며 첨부 화면으로 확인하지 않음 |
| 인쇄용 안내 | 일정 v1의 시간·경험·거리·가상 데이터 안내가 한 장 안내에 표시되는지 확인. 물리 프린터 출력은 미확인 |
| 기본 캐릭터 카드 | 자녀·부모님 같은 카드 표시와 900×1120 PNG 파일의 정상 열림 확인 |
| 직접 고른 이미지 | 양쪽 화면에 같은 이미지 반영, 900×1120 PNG 정상 저장·표시 확인 |
| 사진 이용 동의 해제 | 사진이 사라지는 동작을 사용자 확인 완료 |
| 실제 모바일 화면·Web Share | 수동 확인 대기 |

## 서비스 검증 계획

아래 6개 유형·총 12개 시나리오는 실제 데이터와 AI 연동 이후 실행할 검증 계획이다. 위의 자동 테스트 통과 수와 다른 범위이며, 범용 LLM 비교나 실제 가족 조사는 아직 수행하지 않았다.

| 유형 | 시나리오 1 | 시나리오 2 |
| --- | --- | --- |
| 정상 일정 | 전체 관람이 모든 조건을 충족 | 짧은 관람에서도 필수 경험·식사·휴식 유지 |
| 선호 불일치 | 부모님이 다른 식사 후보를 필수로 선택 | 한 분이 선호한 관람을 다른 분이 거절 |
| 경험과 보행 충돌 | 필수 경험은 가능하나 전체 관람의 총보행 상한 초과 | 짧은 관람도 연속 보행 조건을 초과 |
| 식성·좌석 불일치 | 선택한 식사에 회피 음식 또는 질감 조건이 불일치 | 식사 후보의 입식 좌석 조건이 불일치 |
| 정보 누락 | 접근 구간의 보행·계단 정보 미확인 | 식성 또는 입식 좌석의 핵심 정보 미확인 |
| 휴식 요청 | 완료 구간·예약을 유지한 남은 일정 수정 가능 | 추가 휴식·짧은 접근으로도 남은 조건 충족 불가 |

동일한 원문·가족 선택·조건을 제공한 범용 LLM과 비교해, 확정안의 필수 경험 무동의 삭제·검사 대상 조건 위반·핵심 정보 누락 상태의 확정 각각 0건을 목표로 한다. 확정 불가도 올바른 결과로 평가한다. 가족 사용성 검증에서는 선택·조율 시간과 안내 이해도를 확인하며 측정 전 개선 효과를 제시하지 않는다.

## 재실행

```bash
python -m unittest discover -s tests -p "test_*.py" -v
node --test tests/*.test.js
node --check web/app.js
node --check web/planner.js
python -m compileall -q backend
python scripts/check_public.py
python scripts/build_static.py
```

Windows 게시 스크립트의 응답 대체 검사는 `powershell -NoProfile -ExecutionPolicy Bypass -File tests/publish-demo.tests.ps1`로 실행한다. 실제 배포를 실행하는 명령과 구분한다.

선택 의존성은 `requirements-dev.txt`에 있다. 테스트에서 임시 데이터베이스와 가상 역할을 사용하며 실사용자 자료를 쓰지 않는다.
